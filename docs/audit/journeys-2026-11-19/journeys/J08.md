## Bugs

### J08v-1 — Order history says « Livraison : CRÉÉE → ÉCHEC » for a self-delivered parcel shown as « ENVOYÉE » everywhere else
- Page: /fr/orders/[id] › HISTORIQUE of #CMD-1002 and #CMD-1005 (owner, fr, 1440)
- Severity: Cosmetic
- Type: Text
- Steps: 1. Confirmed order › « Marquer expédiée (livraison propre) ». The delivery row, the order block, the CSV and `GET /orders/:id/shipments` (`status: "sent"`) all read « ENVOYÉE ». 2. Row menu › Échec de livraison › Client absent. 3. Open the order page › Historique.
- Expected: the history uses the parcel's status as the merchant saw it: « Livraison : ENVOYÉE → ÉCHEC ».
- Actual: « Livraison : CRÉÉE → ÉCHEC ». It happened on both #CMD-1002 and #CMD-1005. The public page timeline also starts with « CRÉÉE », which is right there because it is the first step.
- Evidence: .local/qa/journeys/J08v/s11.log (« O2 order page … Livraison : CRÉÉE → ÉCHEC ») · s12.log (« O5 history »)
- Likely cause: apps/api/src/modules/delivery/shipment-effects.service.ts:88 writes `from: o.deliveryStatus`. For a manual parcel, the order's `deliveryStatus` stays `created`, and its label is « CRÉÉE ». The list and the CSV use the manual label `parcel.manual.sent` (« ENVOYÉE ») instead (delivery-overview.service.ts:76).
