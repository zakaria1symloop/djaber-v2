## Bugs

### J14r-1 — « Vues » panel: the « Enregistrer la vue courante… » and « Renommer… » dialogs open with the focus behind the modal — a keyboard user cannot name, save or rename a view
- Page: /ar/orders (owner, ar, 390 × 844) and /fr/orders (fr, 1440 × 900) — same component on the 9 lists of 0a0b4a9
- Severity: Major
- Type: Bug
- Steps: 1. Orders list, Tab to « العروض » (Tab 26), Enter: the panel opens, focus on its first row ✓. 2. Tab to « حفظ العرض الحالي… », Enter. 3. Type a name. 4. Press Tab / Shift+Tab / Enter.
- Expected: the name dialog takes the focus (the field has `autoFocus`), Tab stays inside the modal (07 « WCAG 2.1 AA … keyboard », 2.1.1 / 2.4.3), typed letters go to « اسم العرض ».
- Actual: the dialog opens but `document.activeElement` is the « العروض » chip under the overlay (`elementFromPoint` = `fixed inset-0 z-40 bg-black/70`) at +50 ms, +400 ms and +2.5 s. Typed « abc » goes nowhere (field still empty). Tab goes to « العرض: الكثافة والأعمدة » and Shift+Tab to « عوامل التصفية » — both behind the modal — and never reach the field (fr 1440: « Vues » → « Affichage : densité et colonnes » / « Filtres »). Enter on the chip re-opens the views panel on top of the dialog (2 dialogs open). Same with a mouse click on « + Enregistrer la vue courante… » (focus on the chip, so typing right away is lost) and with « إعادة التسمية… » from a row menu. Only the delete confirmation (« حذف العرض «…»؟ ») gets the focus right (✕, then Tab « إلغاء » / « حذف », Enter deletes). With the field clicked, the rest works: empty name → « حقل مطلوب » (but the field has no `aria-invalid`), duplicate → inline « يوجد عرض بهذا الاسم. » with the input kept, « فتح القائمة على هذا العرض (افتراضي) » checkbox by Space, the default view opens on a clean /orders, an unknown `?view=` → toast « غير موجود أو الوصول مرفوض. » and the URL cleaned.
- Likely cause: packages/ui/src/saved-views.tsx `close(fn)` closes the Radix popover and mounts the dialog in the same render; the popover's close auto-focus puts the focus back on the chip after `SaveViewDialog` (apps/web/src/features/saved-views/saved-views.tsx) has mounted, and the dialog's focus trap does not take it back (the `ConfirmDialog`, mounted from the start, is not affected).
- Evidence: s15b-ar-390.log (« +2500ms after Enter BUTTON «العروض» … COVERED-BY(fixed inset-0 z-40 bg-black/70) », « after typing « abc » … name input value  », « after Enter … dialogs 2 ») · s15c-ar-390.log · s15c-fr-1440.log · s15d-ar-390.log (rename) · shots ar-s15b-after-enter.png, ar-s15b-after-second-enter.png, ar-s15d-rename-dialog.png

### J14r-2 — « Nouvelle vente » sheet: Tab from the product search while its result list is open (empty search) sends the focus to the sheet container, then ✕ → search → container forever (rest of J14-2)
- Page: /ar/sales › « + بيع جديد » (owner, ar, 390 × 844)
- Severity: Minor
- Type: Bug
- Steps: 1. Open the sheet with Enter (focus on ✕), Tab: the search is focused and its list of 5 products opens. 2. Press Tab without typing (e.g. to reach the client or payment first) — or come back to the search by Tab from ✕ after one round.
- Expected: Tab leaves the search for the next control (lines, discount, client…), as it now does after a pick or after Esc.
- Actual: Tab lands on the `DIV[role=dialog]` container, then ✕, then the search (list opens again), then the container… (30 Tabs recorded). Workarounds exist: type something, pick with ↓ / Enter, or Esc (closes only the list ✓) before Tab. With a typed query (« Sav ») Tab correctly goes to « خصم »; the order form's search is fine in both cases (Tab → « الولاية »).
- Likely cause: apps/web/src/features/gds/product-picker.tsx — the list is open whenever the empty search has the focus (`focused && !dismissed`); the Tab handler of `useComboboxList` closes it while the browser moves the focus to a result button that is unmounted, so Radix FocusScope falls back to the container.
- Evidence: s08r-ar-probe-390.log (« 30 Tabs from the search » second round: « BUTTON «إغلاق» → INPUT[combobox] → DIV[dialog] ») · s08s-ar.log (« A: Tab with the list open (empty query) DIV[dialog] », « B: … (query « Sav ») INPUT «sale-discount» », « F/G … BUTTON[combobox] «الولاية» »)
