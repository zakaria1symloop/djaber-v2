### J05r-1 — Order money edit (Admin): a fee / discount / unit price cleared with Backspace turns into « 0 » with the caret before it — typing 500 saves 5 000
- Page: /fr/orders/01a1eea2-27c5-7b16-b963-c11ca62e7614 (#CMD-1001, CONFIRMÉE) › ARTICLES › Modifier (owner, fr, 1440 px) — the new Admin money edit of the J05-4 fix
- Severity: Major
- Type: Bug
- Steps: 1. ARTICLES › « Modifier ». 2. Click in « Frais de livraison » (600), press End, Backspace until empty. 3. Type `500`. 4. Same on « Remise » and on a line « Prix unitaire ». 5. « Enregistrer ».
- Expected: the field reads « 500 » (an emptied field stays empty while typing, like the new-order form and the payment dialog, where the same keys give 500); the merchant saves what he typed.
- Actual (reproduced in two scripts, s13 and s13b): after the last Backspace the field shows « 0 » with the caret at position 0, so `500` becomes « 5 000 »; select-all + `500` gives 500, Delete from the start gives 500. Cause: `amountOf('')` returns 0 and the controlled `MoneyInput` value becomes « 0 » at once (apps/web/src/features/orders/page/blocks.tsx, `onValueChange={(v) => …amountOf(v)}`). ORDERS-01 family, on the money fields added on 16/11.
- Evidence: .local/qa/journeys/J05r/s13.log (« fee "500" → 5 000 | discount "500" → 5 000 », « price "1 100,00" → 10 100 », PATCH body) · .local/qa/journeys/J05r/s13b.log (« (a) fee after backspaces "0" caret 0 » → « 5 000 ») · .local/qa/journeys/J05r/shots/fr-s13-items-saved.png · fr-s13b-fee-backspace.png

### J05r-5 — Arabic order page crashes (« تعذّر التحميل ») for an order that has a « Programmer un rappel » line in its history
- Page: /ar/orders/01a1eea3-9d4b-7afd-b999-414c370fc3e3 (#CMD-1002, RETOURNÉE) (owner, ar, 1440 and 390 px)
- Severity: Major
- Type: Bug
- Steps: 1. In fr, #CMD-1002 › Actions › « Programmer un rappel » › « Dans 1 h » › Programmer (history line « Rappel : 18 nov., 14:38 »). 2. Switch to Arabic and open the order (any later status; here it was then shipped, delivered and returned).
- Expected: the Arabic order page (history line with the callback time).
- Actual (3 times: s21 at 1440 and at 390, probe): the whole page is the error card « تعذّر التحميل · حدث خطأ (المرجع —). · إعادة المحاولة », console `RangeError: Invalid time value` (orders/[id] page chunk). The same order opens in fr and en; #CMD-1001 and #CMD-1003 (no « Rappel » line) open in ar. Cause: the API sends the `callbackAt` history value already formatted for the locale (`GET /orders/:id` history `{"field":"callbackAt","to":"18 نوفمبر، 02:38 م"}`, fr « 18 nov., 14:38 »), and the J05-2 fix `historyParams` (apps/web/src/features/orders/logic.ts) feeds that text to `new Date()` → `algiersTime()` → `Intl.DateTimeFormat.format(Invalid Date)` throws. Every order with a callback scheduled from Actions / the « Programmer un rappel » dialog is unreadable for an Arabic-speaking merchant (in fr it only works because Chrome happens to parse « 18 nov., 14:38 »).
- Evidence: .local/qa/journeys/J05r/s21.log (« [ar-1440] B » and « [ar-390] B » empty) · .local/qa/journeys/J05r/probe-ar-B.log (RangeError) · .local/qa/journeys/J05r/probe-hist.log (history values ar / fr) · .local/qa/journeys/J05r/shots/ar-s21-1440-B.png
